Spectra Peel

An offline PWA that peels noise and stems out of an audio file on your own phone or desktop, and shows you exactly what each model took away. This page records every decision from the design grilling and the build order for v1.

input energyremoved energy (input minus output)illustrative, 0 to 12 kHz, 8 s

Summary

File-based audio processing in the browser: load one file (up to an hour), run on-device models over the whole file or a time range, listen, compare, export. Live mic processing is out of scope. Two operations ship in v1: speech denoise with DeepFilterNet3 and four-stem separation with HT-Demucs. The thing nobody else does is the view: a spectrogram of what each model removed, plus live spectrum curves or a waterfall while you scrub.

Architecture

The UI thread never decodes, runs a model or touches PCM in bulk. Four workers and one AudioWorklet do the heavy work, and OPFS is the only place audio lives between steps.

Edit model

A project is one source plus an append-only log of operations. Undo pops the log and deletes the layers that op produced. The removed layer is a residual: the mixer subtracts two decoded integer streams, so it is exact and costs no disk.

type Range = { start: number; end: number } // samples at the source rate

interface Op {
  id: OpId;
  kind: "denoise" | "separate";
  input: LayerId | "source";
  range?: Range;
  model: { id: string; sha256: string };
  engineVersion: string;
  outputs: LayerId[];
  state: "queued" | "running" | "paused" | "done" | "failed";
}

type LayerData =
  | { kind: "flac"; path: string }
  | { kind: "residual"; minuend: LayerId | "source"; subtrahend: LayerId };

interface Layer { id: LayerId; label: string; producedBy: OpId; range?: Range; data: LayerData }
interface MixState { gains: Record<LayerId, number>; muted: Set<LayerId>; solo?: LayerId; ab: "input" | "mix" }

The FLAC row is an estimate, not a measurement: music usually lands at 55 to 60 percent of raw, sparse stems far lower. M1 measures it. Before any operation the app shows its storage and time estimate against navigator.storage.estimate() and refuses if it will not fit.

Milestones

Each milestone is one PR. Work on the next one starts on a branch stacked on the previous, so review never blocks building.

Repo, tooling, deploy, local spike

Done when the deployed URL reports crossOriginIsolated === true and desktop spike numbers are in docs/spike-results.md.

  • Bun workspace, tsconfig, oxlint, oxfmt, Vitest, Playwright, prek hooks
  • cloudflare.config.ts assets-only Worker with SPA fallback, COOP/COEP headers verified
  • GitHub Actions: lint, typecheck, test, headless WASM smoke, preview deploy per PR
  • Spike: DFN3 and Demucs vocals specialist (fp32) in a worker, 30 s clip in overlapping chunks
  • Spike reports provider used, shader-f16, load time, real-time factor, peak memory incl. GPU buffer sizes
  • CONTEXT.md with the domain terms from this page

Import and view

Done when a one-hour file imports with flat memory, scrubs instantly, and the live view toggles between curves and waterfall.

  • Decode worker: Mediabunny to PCM chunks to 16-bit FLAC plus frame index
  • Peaks pyramid and spectrogram tiles, custom canvas renderer
  • Reader worker, SAB ring buffer, AudioWorklet mixer, per-layer analysers
  • Project list with sizes and delete, opfs-ownership.md
  • Screen layout chosen from the options artifact

Denoise

Done when DFN3 runs on a file or range, the removed layer is audible and visible, and the golden tests pass.

  • Engine: chunking, overlap-add, range padding and edge crossfades (TDD)
  • Inference worker with ['webgpu', 'wasm'], 48 kHz mono resampling
  • DFN3 DSP in TS: 960-point STFT with Vorbis window, 32-band ERB features, running normalisation, order-5 deep filter, ERB mask, overlap-add synthesis (contract in the model card)
  • Op log, layers, mix, A/B, undo; residual layer
  • Removed-energy overlay on the static spectrogram
  • reference/ uv project and golden parity in Vitest under Node; DFN3 parity against the official deepfilternet 0.5.6 package

Export and offline install

Done when the app installs, works in flight mode, and exports a one-hour mix to disk without a memory spike.

  • Encode worker: WAV, FLAC, M4A, Opus; save picker on desktop, Web Share on Android
  • Hand-written service worker, precache manifest, update toast that waits for idle
  • Model library UI: sizes, SHA-256 check, storage.persist()

Stems, fast path

Done when htdemucs produces four stems on desktop and, if the spike says go, on your phone, surviving a backgrounded tab.

  • Phone spike run on the deployed /spike/ page: the go/no-go
  • htdemucs 4-stem op at 44.1 kHz stereo
  • Chunk checkpoints, resume after suspend, Wake Lock, progress and ETA
  • Storage and time estimate before running

Stems, best quality (after v1)

Done when per-stem specialists beat htdemucs on the SDR floor and desktop can run the full ft bag.

  • Specialists downloaded on demand, one model resident at a time
  • Pipelining: fetch the next model while the current one runs; batch chunks per session
  • Concurrency setting from deviceMemory and hardwareConcurrency
  • Port of the ~250-line ft-bag aggregator, parity-tested

Risks and open questions

Does cf serve COOP/COEP?

Undocumented. Fallback is a tiny Worker that stamps both headers, or Wrangler until cf is stable. Settled in M0.

HT-Demucs in ORT Web: currently a no-go

Desktop spike: the published exports fail to load (float64 in the iSTFT). Patched to float32 they load, but run about 9x slower than real time on an RTX-class GPU through WebGPU, and run out of the 4 GB wasm32 heap on wasm. Next lever is graph simplification with fixed shapes. If that fails, M4 needs a different model, a server option, or desktop-only stems. Details in docs/spike-results.md.

Phone memory with fp32 specialists

About 316 MB of weights plus activations. A crash means fp16 conversion and our own model repo move into M4.

Hugging Face under COEP require-corp

Resolved: the spike fetches DFN3 from Hugging Face on a cross-origin isolated page.

Which phone?

Model and Chrome version still needed for the spike report.

Can bun build --compile embed onnxruntime-node?

Only matters for the CLI. Checked when that work starts.
